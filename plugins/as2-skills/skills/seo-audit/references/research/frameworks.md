## 3. React 19 (client-rendered or framework-rendered)

| rule-id | check (what to look for in source) | layer | severity + why | source URL | quoted passage |
|---|---|---|---|---|---|
| FW-REACT-01 | React 19: `<title>`, `<meta>`, `<link>` rendered in any component are hoisted to `<head>` — acceptable replacement for react-helmet for simple cases. Check: exactly ONE `<title>` rendered at a time per page (multiple → all placed in head, behavior undefined); `<title>` child must be a single string (use template literal). | source | medium — duplicate titles are undefined behavior | https://react.dev/reference/react-dom/components/title | "You can render `<title>` from any component and React will always place the corresponding DOM element in the document head." / "Only render a single `<title>` at a time. If more than one component renders a `<title>` tag at the same time, React will place all of those titles in the document head." |
| FW-REACT-02 | `<meta>` hoisting: component-rendered `<meta name=… content=…>` is placed in head; `<meta itemProp>` and `<link itemProp>` are NOT hoisted (they stay in the body as microdata). Check a canonical `<link rel="canonical">` rendered by a page component is a single instance. | source | low–medium | https://react.dev/reference/react-dom/components/meta | "React will always place the DOM element corresponding to the `<meta>` component within the document’s `<head>`, regardless of where in the React tree it is rendered." / "if `<meta>` has an `itemProp` prop, there is no special behavior" |
| FW-REACT-03 | `<link>` hoisting for canonical/icon/etc.: "React will in most cases place the corresponding DOM element in the document head"; `rel="stylesheet"` needs `precedence` for the special handling. | source | low | https://react.dev/reference/react-dom/components/link | "You can annotate the document with links to related resources such as an icon, canonical URL, or pingback. | FW-REACT-04 | Hoisting happens at render; in a client-only app (Vite SPA, no SSR) these tags still only exist after JS runs — they are NOT in the initial HTML response.
