# Research: AI crawlers, AI search surfaces, llms.txt, Bing (rule prefixes `AI-` and `BNG-`)

Fetch date for every citation: **2026-10-12**. All URLs below were fetched this session (read tool, browser render for Bing's JS-only help pages, or `curl` for the IP-range JSON endpoints). Quotes are verbatim, trimmed to <= 2 sentences.

## 0. Read first (blockers, caveats, surprises)

- **No vendor statement exists for JS execution by OpenAI, Anthropic, Perplexity, or Meta crawlers.** I read each vendor's crawler page in full; none says whether the crawler runs JavaScript. This is the finding: the "AI crawlers don't run JS" claim in SEO blogs is **not backed by any vendor doc**. The only vendor-stated facts are: Google renders with evergreen Chromium; Bing renders with Edge and warns against client-side-only content; Apple "may render"; Common Crawl says "JavaScript is not executed". Third-party measurements (a Vercel/MERJ Dec-2024 study is repeated by SEO blogs in search results) were seen only as search snippets, NOT fetched, so they are leads only. The raw-HTML-contains-content check (AI-021) is therefore marked partially `heuristic`.
- **Google says llms.txt is not used by Google Search**, while Chrome's Lighthouse has an optional audit for it. See section 4.
- Bing's Webmaster Guidelines page renders only with JavaScript (the plain fetch returns an empty shell). I read it via a headless browser; text quoted below is the rendered page text.
- Credentials: none of the AI-crawler checks need credentials (robots.txt, HTTP headers, HTML, IP JSON files are public). Search Console (Google) and Bing Webmaster Tools (BWT) data are optional add-ons; degrade by marking those checks `not-verifiable-without-credentials` instead of failing.

## 4. llms.txt: explicit status section

**Status (CITE):** llms.txt is a community **proposal**, not a ratified standard; I found no standards-body (IETF/W3C) publication in what I fetched.
- llmstxt.org: "A proposal to standardise on using an `/llms.txt` file to provide information to help agents use a website." Author: Jeremy Howard. Published: September 3, 2024; Modified: August 10, 2026 ("v2"). Source: https://llmstxt.org/ (page meta `author: Jeremy Howard`, `dcterms.date: 2024-09-03`; body "Published September 3, 2024 / Modified August 10, 2026").
- Proposal repo: https://github.com/AnswerDotAI/llms-txt (Apache-2.0, Jupyter Notebook; 2656 stars / 108 open issues at fetch). README says: "The `llms.txt` specification is open for community input." (https://llmstxt.org/ "Next steps"). Repo README titled "The /llms.txt file, v2", author Jeremy Howard.
- Format (llmstxt.org "Format"): "An H1 with the name of the project or site. This is the only required section"; optional blockquote summary; optional non-heading markdown; zero or more H2-delimited "file lists" where each item is "a required markdown hyperlink `[name](url)`, then optionally a `:` and notes". File lives at `/llms.txt` "or at any subpath"; v2 also recommends `<link rel="alternate" type="text/markdown">` / `rel="describedby"` or an HTTP `Link:` header, and `.md` page twins.
- llmstxt.org's own expectation: "Our expectation was that llms.txt would mainly be useful for *inference* rather than *training*."

**Does any major search/AI vendor document consuming it?**
- **Google Search: documents NOT using it** (CITE): "Google Search itself doesn't use them." https://developers.google.com/search/docs/fundamentals/ai-optimization-guide (also: "you can ignore tactics like ... creating unnecessary AI text files (like llms.txt)").
- **Chrome Lighthouse (a Google product, but a lab tool, not Search): has an audit**, explicitly optional: "The `llms.txt` file is an emerging convention used to provide a machine-readable summary of a website's content". "If the file is not provided by the server (resulting in a 404), the audit is marked as Not Applicable (N/A), as providing the file is optional at the moment." Lighthouse "flags the pages if a server error occurs when attempting to retrieve the `llms.txt` file." https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt (last updated 2026-05-05). Verified rule: a 5xx on `/llms.txt` is the only failing state.
- **OpenAI, Anthropic, Perplexity, Apple, Meta, Common Crawl, Microsoft/Bing:** **none found.** Their crawler pages (section 1) do not mention llms.txt, and the Bing Webmaster Guidelines text I rendered contains no occurrence of "llms" (I grepped the saved text; matches only for IndexNow). Note llmstxt.org says "The AI labs themselves publish llms.txt files for their own developer docs" (OpenAI, Anthropic, Gemini): that is *publishing for their own docs*, which is not a statement that their crawlers/products consume third-party llms.txt files. I did not search each lab's whole documentation set, so "none found" is bounded by the pages fetched this session.
