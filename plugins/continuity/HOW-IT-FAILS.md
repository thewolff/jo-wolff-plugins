# How continuity fails

Every piece that can fail, how it fails, where the failure is visible, and what the person does
about it. `ledger gate check` checks the mechanical parts (the hooks survive five fault inputs;
faults leave an errors.log line and a systemMessage; the skill has a "When this can't run"
section; the block text names a command); this table is the part a person reads.

| Piece | Fails how | Visible where | The person does |
|---|---|---|---|
| `hooks/pre-compact.mjs`, `hooks/session-start.mjs`, `hooks/user-prompt-submit.mjs`, `hooks/stop.mjs` (each hook) | stdin not JSON; the handler throws; no answer in 4 s (`handle()` runs on a worker thread; the main thread's timer ends the run and a late answer is dropped) | one line in `${XDG_STATE_HOME:-~/.local/state}/continuity/errors.log`; a `systemMessage` (`continuity <event> failed open: …`) | nothing for one line; a repeating line is a bug: open an issue with the line |
| `hooks/pre-compact.mjs` (the save) | the state directory cannot be created or the snapshot cannot be written | heartbeat outcome `failed:<code>` (when the heartbeat itself can land) and an errors.log line naming the path and the code; on Claude Code the summary instructions are printed anyway and the restore after the compaction says the state was not restored, with the code; under OMP a `systemMessage` naming the path; the liveness line at the next start says the save never succeeded, with the code | fix the permission on the named path; compaction already proceeded without the snapshot |
| `hooks/pre-compact.mjs` (the summary instructions, Claude Code) | the hook faults, so the runner prints its own `{ systemMessage }` JSON instead of the plain text; a Claude Code build that stops reading PreCompact stdout as summary instructions; a summary that ignores them | no `## Handoff` section at the end of the compaction summary; the restore's notice still says no handoff file was written | write handoffs with `/continuity:handoff` before long sessions compact; a fault is also an errors.log line |
| `hooks/session-start.mjs` (the no-handoff notice, Claude Code) | the snapshot is missing, stale or unparseable, so the save cannot say whether a handoff was present | no notice; the restore's `this compaction's state was not restored` line stands instead | read that line; it carries the save's outcome |
| `hooks/pre-compact.mjs` (the capture) | `git` absent, failing or slow (every call runs at once inside one 2 s budget, the two handoff-root lookups capped at 500 ms each); the transcript unreadable; a dirty tree with hundreds of paths | a field git did not answer is `(unknown: timed out)` or `(unknown: git status failed (exit N))`, never `(clean)`, and the snapshot is still written; a cut section says so (`… TRUNCATED: N more changed paths not shown`); a payload with no session view at all gets a reconstruction section that names itself one | read the repository; run `git status --short` before trusting an unknown field |
| `hooks/session-start.mjs` (the restore) | no snapshot for this session; one older than a day; one that does not parse; one that with its heading and notices does not fit whole in what the liveness line leaves of the 20,000-character restore guard | no snapshot, a stale one or a broken one: nothing restored, and in its place the bold `this compaction's state was not restored` notice with this session's recorded save outcome; after it, the rules and notes sections when each is switched on (`rules`, `notesCount`; they follow every compaction, restored or not), then the liveness line. The over-budget case shows the head cut on a character boundary, says `TRUNCATED` with the number of characters shown, the whole context still within the guard, and keeps the file at the named path; it leaves no room in the 20,000-character restore guard, so the rules and notes sections are left out and the systemMessage names them | read the named file directly; a day-old snapshot is left for prune; after a not-restored notice, reconstruct from the repository and the notes directory |
| `hooks/session-start.mjs` (the rules walk, `lib/repo-rules.mjs`, after a compaction) | the payload's cwd missing or not a directory; a rules file unreadable, empty, a symlink to a path outside the walk root, or the same file reached at two levels; a level at or above `CLAUDE_PROJECT_DIR`; the rendered section (headings, paths, markers and skip lines included) larger than the 9,000-byte section cap, or than what the restore block before it and the notes list leave of the 20,000-character restore guard | the `## Repo rules re-inlined` section, whole, is never over either cap: one line saying nothing was walked, or one `- skipped <path>: <why>` line per file not inlined, and when those lines alone overrun the cap, the ones that fit and `- N more rules files not inlined and not listed: no room in the section`; with no room for even its heading the section is left out and the systemMessage says so; a cut file is cut on a UTF-8 character boundary and ends `(truncated at N bytes; the file is M bytes, read it for the rest)`, N the bytes shown; the largest files are cut first and the smallest land whole; never a silently shortened rule | read the named file; a `no room` skip or a left-out section means the snapshot was large, and the rules files are the ones to open first; `"rules": "off"` drops this section without touching the notes list |
| `hooks/session-start.mjs` (the notes probe, after a compaction) | `notesDir` absent, a file, or unreadable; the walk finds no git root; the list larger than what the restore block before it leaves of the 20,000-character restore guard | one line under `## Durable notes` naming the directory it looked for (relative to the git root of the real cwd, its symlinks resolved, or that cwd when there is no git root); short of room, fewer names are listed, then none (`N entries; no room left in the restore guard to list them`), then the section is left out and the systemMessage says so | set `notesDir` in the config file, or create the directory; `"notesCount": 0` drops this section without touching the rules |
| `hooks/session-start.mjs`, `hooks/user-prompt-submit.mjs` (the liveness line) | the heartbeat file is absent or empty (the hook never ran here, or cannot write); the newest save failed after an earlier success; the hook has run and never succeeded | the bold `no pre-compaction save has ever been recorded`, `the last save failed <age> ago … the last success was <age>`, or `has ever succeeded` text, with the heartbeat path and the outcome; never a healthy line while the newest save failed. After a compaction with nothing restored, `this compaction's state was not restored` with this session's recorded outcome | run one `/compact` in a throwaway session to make the hook run; if the line persists, the named path's permission is the problem |
| `hooks/user-prompt-submit.mjs`, `hooks/stop.mjs` (the pressure check) | on Claude Code the measure is the token usage the last main-thread reply recorded, one turn behind the prompt it gates; with no recorded usage since the last compaction marker it falls back to the transcript's size / 8, which can be off in either direction; no `transcript_path`; a transcript that cannot be measured; a host that sends `token_count` with another meaning; a window's first recorded usage that is itself large (the ask waits for `askMarginTokens` past it) | a usage-based ask names the exact token count; a fallback ask says `(estimate)` and may come early or late; silent when there is nothing to measure; a wrong calibration shows as an ask at an implausible size | compare the size with `/context`; set `askTokens`, `askMarginTokens` or `reaskStepTokens` in the config; a calibrated ask at a wrong size is a bug: open an issue with one `calibration.ndjson` line and the `/context` figure |
| `hooks/user-prompt-submit.mjs`, `hooks/stop.mjs` (the re-arm) | a 0.3 flags file (bare timestamps, no window); a compaction since the last ask; a compaction marker with no `uuid` | the first two count as an earlier window: the ask is due again at the current window's ask point; the third is named by its byte offset, which also never changes; never an ask on every prompt (each ask records the size it was given at, and the next waits for `reaskStepTokens` more) | nothing; answering an ask in one line ends it until the next step or compaction |
| `lib/autocompact.mjs` (a set auto-compact window) | the window set by `--autocompact`, `--settings` or managed settings (not read); a settings file that does not parse or carries an out-of-range value (skipped); a transcript reply with no `message.model` (only the top-level `autoCompactWindow` applies); a model id that canonicalizes to no `modelSettings` key (an alias such as `opus`, an ARN, an unrecognised provider spelling); `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` with no window set on a model that is not a recognised native 1M model (not modelled); Claude Code's buffer before the window differing from the assumed 33,000 (measured, not documented: on Claude Code 2.1.321 with a 300,000 window for claude-fable-5-2, session eacf7986 compacted automatically on 2026-11-10 at 7:03 PM PST at `preTokens` 267,109, 32,891 before the window) | the default ask comes at 175,000 (or the idle point) as if no window were set, or up to the difference earlier or later than `askMarginTokens` before the real compaction; a window that opens past the margin point is asked on its next turn, not `askMarginTokens` past its baseline | set `askTokens` in continuity's config to a size below the window you set |
| `hooks/stop.mjs` (the block) | the mark `sessions/<session>.json` cannot be written; the handoff root resolves somewhere other than where this session wrote its handoff | no block (a block that cannot be recorded is not made); a block after a handoff was written elsewhere | fix the permission on the state directory; the block fires once per step, so answering it in one line ends it |
| `lib/config.mjs` (`${XDG_CONFIG_HOME:-~/.config}/continuity/config.json`) | missing; unreadable; not JSON; not an object; a value of the wrong shape | missing is the defaults with no message; anything else is the defaults for that value and a `continuity: <path> …` line in the next hook output, once per session | fix the file; the line names the key and the value |
| `skills/handoff/SKILL.md` (`/continuity:handoff`) | `.ai/handoffs/` unwritable; `git` missing; the command absent | the skill's "When this can't run" section: the five sections go in the reply, the root is the cwd, the file is written by hand | read the reply; the content is there |
| `lib/handoffs.mjs` (the reader) | a handoff with no frontmatter, no body, `status` not `open`, or older than 7 days; the root resolves differently from where the skill wrote | not shown; the snapshot's handoff section is absent and the restore says `No handoff file was written` (under OMP, `No handoff was written`) | look in `<root>/.ai/handoffs/`; the skill and the reader resolve the root the same way, so a missing file is in another repository or past 7 days |
| `omp/continuity-omp.ts` (the OMP save, `session_before_compact`) | no usable `node` (the host is Bun and none is on PATH or in the usual places); the spawned `hooks/pre-compact.mjs` exits non-zero, prints something other than JSON, or outruns its 8 s budget (the runner's own 4 s deadline plus start-up); the event carries no `preparation` | one `omp-adapter pre-compact.mjs: <why>` line in `${XDG_STATE_HOME:-~/.local/state}/continuity/errors.log`; the compaction proceeds, never cancelled, never given a replacement summary; an empty `preparation` is a save with `intents: []` and a file-operations line saying the host reported none, which the snapshot names as its capture source | set `CONTINUITY_NODE=/path/to/node` for the node case; otherwise read the line; the liveness line at the next compaction says whether the save landed |
| `omp/continuity-omp.ts` (the OMP restore, `session_compact`) | the spawned `hooks/session-start.mjs` fails as above; the host has no `sendMessage`; the hook answers nothing | one `omp-adapter session-start.mjs: <why>` line in `errors.log`; the turn goes on without the restore (the snapshot stays in the state directory for the next compaction's restore, or for prune) | read the named snapshot file directly; `the host has no sendMessage` means an OMP build older than the extension API this needs |
| `omp/continuity-omp.ts` (the trigger) | `auto_compaction_start` was not seen before `session_before_compact` (an OMP build that orders them differently) | the save records `trigger: manual` and the no-handoff `systemMessage` is not shown for that compaction; the snapshot is still written | nothing; `trigger` in the snapshot file is informational |
| `evals/*.scenario.json` (fifteen, one per hook event × outcome, the siblings, the rules walk, the notes probe and the OMP payload) | an outcome the hook returns with no scenario; a scenario whose `after` block fails | `ledger gate check` row `evals` fails naming the event, the outcome or the scenario | `bash e2e/live-run.sh --no-live` replays them offline and names the failing one |
| `e2e/live-run.sh` (the canary) | `claude` missing or cannot log in | exit 75 with the reason on the last line; `ledger canary runs` shows `unavailable` | nothing; the canary tries again tomorrow |
| `scripts/prune.mjs` (retention, declared in plugin.json `state`) | the state directory is unreadable; a file cannot be removed | `pruned: … kept N` on stdout, the file named on stderr; `ledger canary status` shows the prune row | nothing for one night; a repeating line is a permissions problem on the named file |
