# How continuity fails

Every piece that can fail, how it fails, where the failure is visible, and what the person does
about it. `ledger gate check` checks the mechanical parts (the hooks survive five fault inputs;
faults leave an errors.log line and a systemMessage; the skill has a "When this can't run"
section; the block text names a command); this table is the part a person reads.

| Piece | Fails how | Visible where | The person does |
|---|---|---|---|
| `hooks/pre-compact.mjs`, `hooks/session-start.mjs`, `hooks/user-prompt-submit.mjs`, `hooks/stop.mjs` (each hook) | stdin not JSON; the handler throws; no answer in 4 s (`handle()` runs on a worker thread; the main thread's timer ends the run and a late answer is dropped) | one line in `${XDG_STATE_HOME:-~/.local/state}/continuity/errors.log`; a `systemMessage` (`continuity <event> failed open: …`) | nothing for one line; a repeating line is a bug: open an issue with the line |
| `hooks/pre-compact.mjs` (the save) | the state directory cannot be created or the snapshot cannot be written | heartbeat outcome `failed:<code>` (when the heartbeat itself can land); a `systemMessage` naming the path and the code; the liveness line at the next start says the save never succeeded, with the code | fix the permission on the named path; compaction already proceeded without the snapshot |
| `hooks/pre-compact.mjs` (the capture) | `git` absent, failing or slow (every call runs at once inside one 2 s budget, the two handoff-root lookups capped at 500 ms each); the transcript unreadable; a dirty tree with hundreds of paths | a field git did not answer is `(unknown: timed out)` or `(unknown: git status failed (exit N))`, never `(clean)`, and the snapshot is still written; a cut section says so (`… TRUNCATED: N more changed paths not shown`); a payload with no session view at all gets a reconstruction section that names itself one | read the repository; run `git status --short` before trusting an unknown field |
| `hooks/session-start.mjs` (the restore) | no snapshot for this session; one older than a day; one that does not parse; one over 20,000 characters | nothing restored, the liveness line alone; the over-budget case shows the head, says `TRUNCATED` and keeps the file at the named path | read the named file directly; a day-old snapshot is left for prune |
| `hooks/session-start.mjs`, `hooks/user-prompt-submit.mjs` (the liveness line) | the heartbeat file is absent or empty (the hook never ran here, or cannot write); the newest save failed after an earlier success; the hook has run and never succeeded | the bold `no pre-compaction save has ever been recorded`, `the last save failed <age> ago … the last success was <age>`, or `has ever succeeded` text, with the heartbeat path and the outcome; never a healthy line while the newest save failed. After a compaction with nothing restored, `this compaction's state was not restored` with this session's recorded outcome | run one `/compact` in a throwaway session to make the hook run; if the line persists, the named path's permission is the problem |
| `hooks/user-prompt-submit.mjs`, `hooks/stop.mjs` (the pressure check) | on Claude Code the measure is the token usage the last main-thread reply recorded, one turn behind the prompt it gates; with no recorded usage since the last compaction marker it falls back to the transcript's size / 8, which can be off in either direction; no compaction marker in the transcript, so the fallback counts bytes from before an earlier compaction; no `transcript_path`; a transcript that cannot be measured; a host that sends `token_count` with another meaning | a usage-based warning names the exact percentage; a fallback warning says `(estimate)` and may come early or late; silent when there is nothing to measure; a wrong calibration shows as a warning at an implausible percentage | compare the percentage with `/context`; set `contextTokens` or `threshold` in the config to match; a calibrated warning at a wrong percentage is a bug: open an issue with one `calibration.ndjson` line and the `/context` figure |
| `hooks/stop.mjs` (the block) | the once-mark `sessions/<session>.json` cannot be written; the handoff root resolves somewhere other than where this session wrote its handoff | no block (a block that cannot be made once-only is not made); a block after a handoff was written elsewhere | fix the permission on the state directory; the block fires once, so answering it in one line ends it |
| `lib/config.mjs` (`${XDG_CONFIG_HOME:-~/.config}/continuity/config.json`) | missing; unreadable; not JSON; not an object; a value of the wrong shape | missing is the defaults with no message; anything else is the defaults for that value and a `continuity: <path> …` line in the next hook output, once per session | fix the file; the line names the key and the value |
| `skills/handoff/SKILL.md` (`/continuity:handoff`) | `.ai/handoffs/` unwritable; `git` missing; the command absent | the skill's "When this can't run" section: the five sections go in the reply, the root is the cwd, the file is written by hand | read the reply; the content is there |
| `lib/handoffs.mjs` (the reader) | a handoff with no frontmatter, no body, `status` not `open`, or older than 7 days; the root resolves differently from where the skill wrote | not shown; the snapshot's handoff section is absent and the restore says `No handoff was written` | look in `<root>/.ai/handoffs/`; the skill and the reader resolve the root the same way, so a missing file is in another repository or past 7 days |
| `evals/*.scenario.json` (twelve, one per hook event × outcome and the siblings) | an outcome the hook returns with no scenario; a scenario whose `after` block fails | `ledger gate check` row `evals` fails naming the event, the outcome or the scenario | `bash e2e/live-run.sh --no-live` replays them offline and names the failing one |
| `e2e/live-run.sh` (the canary) | `claude` missing or cannot log in | exit 75 with the reason on the last line; `ledger canary runs` shows `unavailable` | nothing; the canary tries again tomorrow |
| `scripts/prune.mjs` (retention, declared in plugin.json `state`) | the state directory is unreadable; a file cannot be removed | `pruned: … kept N` on stdout, the file named on stderr; `ledger canary status` shows the prune row | nothing for one night; a repeating line is a permissions problem on the named file |
