# How brb fails

The receipt the repository test bar asks for before a plugin ships: every piece that can fail,
how it fails, where the failure is visible, and what the person does about it. `ledger gate
check` checks the mechanical parts (the hooks survive five fault inputs; faults leave an
errors.log line and a systemMessage; every skill has a "When this can't run" section; every deny
text names a command); this table is the part a person reads.

| Piece | Fails how | Visible where | The person does |
|---|---|---|---|
| `hooks/user-prompt-submit.mjs`, `hooks/stop.mjs`, `hooks/session-start.mjs` | stdin not JSON; the handler throws; no answer in 4 s (`handle()` runs on a worker thread, the main thread's timer ends the run and a late answer is dropped) | one line in `${XDG_STATE_HOME:-~/.local/state}/brb/errors.log`; a `systemMessage` (`brb <event> failed open: …`) | nothing for one line; a repeating line is a bug: open an issue with the line |
| `away.json` (the hold) | does not parse, or has no `since` | read as home: the next `brb` starts a fresh hold, the Stop hook holds nothing, `back` says not away | type `brb` again; the digest file, if any, is still there and the next `back` prints it |
| `back` (the digest reaching the person) | the surface renders no hook frame (the Claude mobile app), or the agent does not reply with the digest it was handed | the digest is archived either way (`archive/<ts>.md`); the hook's `systemMessage` shows where frames render; the agent's reply is the copy every surface shows, and `brb: Jo is back … Reply with the digest below verbatim as your whole message` is its instruction (`lib/text.mjs` `backInstruction`) | read the agent's reply; if it is not the digest, open `archive/<ts>.md` under the session's state directory, and open an issue with the reply |
| `digest.md`, `away.json` writes | the state directory cannot be written | one errors.log line (`Stop could not write state: …`) and a `systemMessage` (`brb Stop could not write its state (…)`); an on-fire line in the same message still surfaces (fires are built before any write); the stop proceeds; the ask is still on screen in the agent's message | fix the directory's permissions; read the message on screen |
| `transcript_path` (tool-less stop counting) | no path (OMP `--no-session`), unreadable, rotated | every `stop_hook_active` stop counts as tool-less (a first stop counts when its message is byte-identical to the previous stop's), so `idleStops` still ends the loop, and a continuation with nothing new is released by the guard whatever tools it ran; `away.json` `lastStop.transcript` is `false` | nothing; the agent still stops on an `idle:` line, on the guard, after `idleStops` and after three continuations with nothing new |
| `transcript_path` in a line shape that is neither Claude Code's (`assistant` rows, `tool_use`) nor OMP's (`message` rows, role `assistant`, `toolCall`) | read as zero tool calls | the agent is let go after `idleStops` stops, whatever it ran (`brb: 2 stops with no tool calls between them; …`) | open an issue with one line of the transcript; `countToolUses` in `lib/stop-core.mjs` needs the shape |
| `transcript_path` lagging at Stop time (the hooks reference says the file "isn't guaranteed to include the final message at Stop time on all versions"; not observed here) | tool rows written just before the stop are not on disk yet, so the stop counts zero tool calls | a working continuation with nothing new is released silently by the guard; the late rows count at the next stop, since the line marker is recorded | type a prompt to start the agent again; an `idle:` line or a new ask in the next message is unaffected |
| the on-fire `osascript` notification (macOS) | `osascript` missing or refused; Notification Center off | nothing: the spawn is detached and ignored; the `systemMessage` and the OSC 9 `terminalSequence` still carry the line | nothing; `BRB_DESKTOP_NOTIFY=off` turns the attempt off |
| the OSC 9 `terminalSequence` | the terminal does not render OSC 9 | no banner; the `systemMessage` still shows in the transcript | nothing |
| `scripts/brb.mjs hold` (the agent's command) | not away; no item text; several sessions away and none named; the state directory cannot be written | `not away; say it to Jo` on stdout, exit 0, nothing written; usage on stderr, exit 1; `several holds are away (…); pass --session <id>` on stderr, exit 1; `brb hold: could not write the digest (…); say it to Jo` on stderr, exit 1 | nothing for the first (the agent asks in its reply, and the Stop hook's backstop files what it shows); the others leave the ask on screen once, where the backstop files it; a repeating write error is a permissions problem on the session directory |
| `away.lock` (per-session lock around every `away.json` read-modify-write: `hold`, `brb`, `back`, the new-turn reset, the Stop hook's read-merge-write, and `pending`'s read; holds `<pid> <token>`) | another live writer holds it past 2 s; a crashed writer left it behind; a hung writer holds it past 60 s | `brb hold: could not write the digest (brb: the hold is locked (<path>, held by pid N); try again in a moment); say it to Jo`, exit 1; in the Stop hook, `brb Stop could not write its state (…)` beside any fire, one errors.log line, the stop proceeds; in `pending`, one errors.log line and the word proceeds; a lock whose pid is dead (`kill(pid, 0)` → ESRCH) or older than 60 s is taken over at once (rename then remove, so two waiters cannot each remove the other's fresh lock) | nothing; the next attempt goes through once the live holder releases (every holder is a hook or a command bounded in seconds) |
| the Stop hook's backstop | the agent keeps showing asks | each turn's first stop that shows one is blocked once (`brb: N item(s) moved to the digest; …`); the next stop in that turn goes through the release rules, and after `idleStops` tool-less stops the backstop yields | nothing; the items are in the digest either way, and the block reason is on screen only as a hook line |
| `~/.config/brb/config.json` | missing, unreadable, malformed, a field that is not a non-negative integer | the defaults (`onFireCap` 3, `idleStops` 2), silently | fix the file; nothing is lost meanwhile |
| `omp/brb-omp.ts` (the OMP adapter) | the spawn fails, exits non-zero, prints junk, outruns its budget (5 s prompt/start, 10 s stop) | one `omp-adapter …` line in errors.log; the word is still handled (it never reaches the model), the turn starts without the context, the stop is allowed | nothing for one line; a repeating line names the hook, run it by hand with the same stdin |
| `evals/*.scenario.json` (one per hook event × outcome) | an outcome the hook returns with no scenario; a scenario whose `after` block fails | `ledger gate check` row `evals` fails naming the event, the outcome or the scenario | fill the scenario; `bash e2e/live-run.sh --no-live` replays them offline |
| `e2e/live-run.sh` (the canary) | `claude` missing or cannot log in | exit 75 with the reason on the last line; `ledger canary runs` shows `unavailable` | nothing; the canary tries again tomorrow |
| `scripts/prune.mjs` (retention, declared in plugin.json `state`) | the state directory is unreadable; a file cannot be removed | `pruned: … kept N` on stdout, the file named on stderr; `ledger canary status` shows the prune row | nothing for one night; a repeating line is a permissions problem on the named file |
| `mods/band/register.mjs` (the away band, a Claude Code mod), `mods/band/query.mjs` and `mods/band/act.mjs` | `node` missing from Claude Code's PATH; the query or an action denied, over its 5 s budget, or printing junk; `away.json`, `digest.md` or `checklist.json` a directory, a link or over 64 KiB (checked on the open descriptor the read uses); the home probe refused (`$.fs.exists` or the session id rejecting); a hook that throws | the band is cleared and one dim transcript line `brb band: query: …`, `brb band: probe: …` or `brb band: <back\|done\|clear>: …` per distinct error, or `brb band: <hook>: …`; the event passes on; the hooks hold as before and `pending` and `back` still print the digest | nothing for one line; a repeating line names the fault; `node mods/band/query.mjs --session <id>` by hand prints the snapshot the band would draw |
| The band never drawn (a host that does not raise `AbovePrompt`: Claude Code's type file says terminal only; possibly Desktop) | the render site is never asked to draw | no band and no buttons; from the first 5 s tick the 0.3.x status line under the prompt (`⚠ brb: away 40m · 3 held · say back`, after back `⚠ brb: back · 2 to act on`) | type `back`; the line and the hooks' own lines carry the hold |
| The band across `/clear`, `/resume`, `/branch` (`mods/band/register.mjs` begin/stop) | the host fires `session.end` then `classic.SessionStart` with a source other than `clear`, `resume` or `fork`, or not at all | the mod stops at `session.end` (no band, no poll) and starts again only on those sources; with none, no band until the window is reopened, while the hooks hold and `back` work as before | reopen the window; `/plugin` reload starts `session.start` again |
| The Back button (`$.prompt.submit({ text: "back", asUser: true })`) | act.mjs fails (denied, over 5 s, junk); Claude Code refuses or drops the prompt (`{ drop }`: after Esc stopped a turn, a `-p` turn limit) or the call rejects; a Claude Code without `asUser` on `$.prompt.submit` delivers the word wrapped in a sentence naming the mod, so the hook does not read it as `back`; the agent is working; the hold the press was made for ends or is replaced before either check; the host never fires `turn.complete` for the running turn; the mod loaded mid-turn on a host whose band gives no `isWorking` (it saw no turn event yet, so it takes the session as idle) | a failure: one dim line `brb band: back: …` and a toast `brb: Back failed: <reason>; type back`, the band as it was and the button live again (a failure from an earlier conversation shows nothing). Without `asUser`: the prompt reaches the agent as a message from the mod and the hold stays. Working: the band reads `Back pressed · ending the hold` until the turn ends, then `back` is sent if the same hold is still on. Hold ended or replaced: nothing sent, no toast, the band shows the new state. No `turn.complete`: the press waits and the band keeps reading `Back pressed · ending the hold`. Loaded mid-turn without `isWorking`: `back` is sent at once and Claude Code runs it after the turn; a `back` typed in that turn then gets the `you were not away` reply | type `back` |
| `checklist.json` (the after-back checklist) | does not parse, or a write fails (state directory unwritable) | read as no checklist: the band clears; a failed Done or Clear writes `brb band: done: …` or `brb band: clear: …` and the row stays as it was | nothing; the digest is also in `archive/<when>.md`; delete `checklist.json` to clear a stuck band |
| The hidden transcript (`mods/band/register.mjs` row hooks, `mods/band/hide.mjs` ledger) | a row hook throws or the host refuses its tree; the query fails or has not answered yet; a row from before the hold was never drawn while home (a conversation reopened while away, a row the host first draws during the hold); the ledger's 20,000-id set is full in a very long conversation | a fault: the row draws as Claude Code draws it and one dim line `brb band: ui.render <site>: …` per distinct error. No answer: every row draws as is until a query answers. An old row first drawn during the hold: hidden with the hold's rows. Full: rows it cannot place draw as is for the rest of the conversation | nothing for one line; `back` shows every row again; `{ "hideRows": "off" }` in config.json shows them while away |
| Rows staying dim after `back` | the surface does not redraw a row already on screen when the mod calls `$.ui.invalidate("ui.render")` (possible for finished rows the classic terminal renderer printed to scrollback; not observed) | `held while away · say back` lines still in the transcript after the hold ended and the band turned into the checklist | set `{ "hideRows": "off" }` in `${XDG_CONFIG_HOME:-~/.config}/brb/config.json`: from the next query no row is hidden in any hold; ctrl+o does not help (the transcript viewer draws through the same render sites). The stored conversation is unchanged; open an issue with the surface and version |
| The `hideRows` switch (config.json, read by `mods/band/query.mjs` each query) | the file cannot be read or parsed, or `hideRows` is a value other than `"on"`, `true` or `"off"`, `false` | every row draws as Claude Code draws it while away; the band, the digest and the away text are unchanged | fix the file, or leave it: hiding stays off until it parses with `hideRows` on or absent |
| What still shows while away | a permission prompt (not a render site), Desktop's own task rows, possibly the terminal's in-flight streaming preview of a reply, a reply with an `on fire:` line | on screen as usual | answer the permission prompt or leave it; the rest is by design |
| The away text (`prompt.section` on the environment section, `tool.call` context) | a Claude Code before 2.1.321 ignores `breakPromptCache` (from 2.1.299 a running conversation still read the change on the next turn); neither environment section name is in the composition; Claude Code drops a `context` a hook adds to a core result; a running turn makes no tool call after `brb` | the agent narrates while away (its rows are hidden anyway) or misses the instruction for the rest of the running turn; the prompt hook's own away instruction still reaches the next turn | nothing; if replies look wrong after `back`, open an issue with the reply |
